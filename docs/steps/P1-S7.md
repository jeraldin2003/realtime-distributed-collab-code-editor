# P1-S7 — Connection UX

**Depends on:** P1-S6
**Goal:** Users always know the connection state; reconnects are clean.

## Build
1. Status indicator in the header: `Connecting…`, `Connected`, `Disconnected (retrying…)`, with a colored dot. Map from the provider's real status values (verify them in the installed version).
2. While disconnected, show a subtle banner: "Offline. Your edits will sync when you reconnect." Edits remain allowed.
3. After reconnect, text converges with others and the banner disappears.
4. Remote cursors of users who disconnected are removed within a few seconds; no ghost cursors after a refresh.
5. Test (automated where practical): two clients, stop and restart the server (or disconnect one client's socket), edit offline, reconnect, assert convergence. If not practical to automate, document a manual script in the README and say so in the report.

## Files (expected)
`frontend/src/components/{Header.tsx,OfflineBanner.tsx}`, `frontend/src/collab/useCollab.ts`, optional test

## Acceptance
- Stopping the backend shows Disconnected and the banner; restarting shows Connected and clears it.
- Offline typing merges on reconnect with no lost or duplicated text.
- No console errors during disconnect/reconnect.

## Verify
2 tabs: stop backend, type in both, start backend, confirm convergence.

## Do NOT
Custom reconnect logic if the provider already reconnects; local persistence (IndexedDB) of offline edits.
