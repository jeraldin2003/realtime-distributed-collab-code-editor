# P2-S5 — Rename and delete

**Depends on:** P2-S4
**Goal:** Files can be renamed and deleted safely while others are using them.

## Build
1. Rename: double-click or a menu action turns the name into an inline input; same validation as create. Only the `name` field changes, so open editors are unaffected.
2. Delete: menu action with a confirm step (inline confirm, not `window.confirm`). Removes the id from the index.
3. If the file **you have open** is deleted by someone else: show a notice "This file was deleted", destroy its provider and binding, and switch to the first remaining file. If none remain, show an empty state with a "Create file" button.
4. If the open file is renamed by someone else: update the label only; no editor changes.
5. Deleting the last file is allowed by the UI; the empty state must work. Orphaned file docs stay in server memory (known limitation; note in `DECISIONS.md`).
6. Tests for the frontend helpers: rename, delete, delete-while-open handling logic as a pure function where possible.

## Files (expected)
`frontend/src/collab/fileIndex.ts` + tests, `frontend/src/components/{FileList.tsx,EmptyState.tsx,Notice.tsx}`, `App.tsx`

## Acceptance
- Rename in A shows in B; B's open editor keeps working.
- Delete in A while B has that file open: B sees the notice and moves to another file with no errors.
- Delete everything: empty state works; creating a file recovers.
- All checks pass.

## Do NOT
Folders, undo for deletes, trash/restore, persistence.
