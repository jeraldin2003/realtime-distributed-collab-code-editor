# P1-S4 — Starter seed

**Depends on:** P1-S3
**Goal:** The shared file starts with a short starter snippet, inserted exactly once, by the server only.

## Build
1. `backend/src/config.ts`: add `STARTER` (a short TypeScript snippet, 5–10 lines).
2. In the server, seed `DOC_NAME` with `STARTER` only when the document is first created and empty. Find the correct Hocuspocus hook for document load from the installed version (grounding skill). Seeding must be idempotent.
3. Tests: with three clients connecting in sequence, the text equals `STARTER` exactly once. Reconnecting a client does not re-seed.
4. The client must not seed anything.

## Files (expected)
`backend/src/{config.ts,server.ts}`, `backend/src/seed.ts` (optional), `backend/src/*.test.ts`

## Acceptance
- A fresh browser tab shows the starter code. A second tab shows it once, not twice.
- Server restart resets the file to the starter (expected, no persistence).
- Seeding tests pass.

## Verify
Open 3 tabs in sequence; restart the backend and refresh.

## Do NOT
Persistence, seeding from the client, changing the doc name.
