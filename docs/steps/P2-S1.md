# P2-S1 — Backend file model

**Depends on:** P1-S8 (tag `phase-1-complete`)
**Goal:** The backend understands multiple documents and the file index. No frontend change; Phase 1 UI must keep working.

## Build
1. Read `.agents/skills/file-model/SKILL.md` and `docs/ARCHITECTURE.md` (document names, Yjs shapes).
2. `backend/src/docNames.ts`: `INDEX_DOC = "project:index"`, `fileDocName(id)`, `parseDocName(name)` returning `{kind:"index"} | {kind:"file", id} | null`, with the id regex from the architecture doc. Unit tests for valid and invalid names.
3. `backend/src/fileIndex.ts`: pure helpers operating on a `Y.Doc`: `ensureDefaultIndex(doc)`, `createFile(doc, {name, parentId})` (returns id), `renameFile(doc, id, name)`, `deleteFile(doc, id)`, `listFiles(doc)`. Generate ids as lowercase `[a-z0-9-]` (verify regex), unique. Unit tests including concurrent creates merging two docs.
4. Server: accept `INDEX_DOC` and `file:<id>` names (rejecting everything else). Seed `INDEX_DOC` once with the default project (`main` → `main.ts`) when empty. Seed `file:main` with `STARTER` as in Phase 1. Other new file docs start empty.
5. **Cap stays unchanged in this step** (still counts `file:main`). It moves in P2-S2.

## Files (expected)
`backend/src/{docNames.ts,fileIndex.ts,server.ts,config.ts}` and tests

## Acceptance
- Unit tests for doc names and file index helpers pass (create, rename, delete, concurrent create).
- Integration test: client connects to `project:index` and sees one file `main`; `file:main` still has the starter.
- A bad doc name (e.g. `file:../x`, `foo`) is rejected.
- Phase 1 frontend still works unchanged in the browser.

## Do NOT
Touch the frontend. Move the cap. Add persistence. Validate index mutations on the server.
