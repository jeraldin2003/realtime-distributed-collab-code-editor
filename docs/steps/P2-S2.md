# P2-S2 — Index sync and file list

**Depends on:** P2-S1
**Goal:** The frontend connects to the index, shows a live file list, and the user cap is counted on the index doc.

## Build
1. Backend: move the cap to `INDEX_DOC` connections only (see `docs/ARCHITECTURE.md`). `file:<id>` connections are not counted. Update limiter integration tests.
2. Frontend `collab/useIndex.ts`: one provider for `INDEX_DOC`; exposes a reactive, sorted list of `{id, name, type, parentId}` from the `files` map. Use a **shared websocket** for multiple providers if the installed provider supports it (verify), so one browser = one socket.
3. Move the "Room is full" and status logic to the index provider. The file provider (from P2-S3) never decides fullness.
4. Add a left sidebar `FileList` showing file names (flat list). The active file is `main` for now; the editor keeps the Phase 1 binding to `file:main`.
5. Presence count is still derived from awareness on the index provider.

## Files (expected)
`backend/src/{server.ts,connectionLimiter.ts}` tests; `frontend/src/collab/useIndex.ts`, `frontend/src/components/{Sidebar.tsx,FileList.tsx}`, `App.tsx`, `Header.tsx`

## Acceptance
- Sidebar lists `main.ts`; opening a second tab shows the same list.
- `MAX_USERS=2` still blocks a third tab, and the cap counts users, not documents (check the server log count).
- Phase 1 behaviors (sync, cursors, reconnect) still work.

## Do NOT
Switching files, create/rename/delete UI, folders, per-file presence.
